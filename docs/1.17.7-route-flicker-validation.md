# 1.17.7: route-line heartbeat continuity

## Reproduced defect

The published 1.17.6 tree (3d1dff371cbec1c065466d5e98ae4066583867f7; remote commit 1f7c063ef2496f8a0fa2f47fd99343893ed81d1e) revokes the current camera snapshot on every unchanged 500 ms heartbeat. The pending marker includes transport revision and timestamp. Until the next animation frame and asynchronous MessagePort delivery, content-world projection returns null. The 80 ms overlay renderer can observe that gap, hide its SVG, and rebuild it on recovery.

An offline regression wires the production observer into the production bridge and deliberately renders between heartbeat queue, frame, and delivery. Against the unchanged base implementation it fails at `heartbeat pending must not blank unchanged geometry` (null instead of the existing point). Five repeated heartbeats after the fix preserve projection and hit tests; real camera movement still immediately blocks both before delivery.

Command: `node --test --test-name-pattern='identical heartbeat' tests/reinforcement-map.test.cjs`.

## Fix and safety boundaries

The private marker identifies exact mapping geometry: galaxy, camera position/zoom/constants, CSS rectangle and native logical dimensions. Revision/order and observation time/staleness still validate every received snapshot independently. Same-geometry heartbeats therefore retain only an already valid, still-fresh mapping; no general stale-geometry fallback or grace period is introduced. Actual geometry changes, invalidation, scope changes and stale observations remain unavailable.

The main overlay signature now includes only visual route identity, pause state, endpoints and preview state. Scheduling timestamps, counters and other route metadata no longer rebuild identical SVG lines. The static schematic already uses a visual signature and is unchanged.

## Interface layering correction

A second user screenshot visibly shows the cyan route over the native dark topbar. The old fixed body overlay used z-index 140. The current native topbar uses 4 and the sidebar 10; some HUD elements use auto, so simply reducing a late body overlay's z-index is insufficient.

Verified read-only official sources:
- https://oldlight.io/game/galaxy/alpha: direct #app children start with h1.sr-only, canvas#stage, header#hud.
- https://oldlight.io/assets/galaxy-CxbOuUuE.css: SHA-256 78530401c5f054a7d00bc167f2e98c1339bcbc2354903b10a1a1f5c91dae1e30. #app is position:relative without z-index; #stage is unpositioned; #hud is absolute with auto z-index. html/body/#app introduce no transform/filter/contain/isolation stacking context.

The overlay now mounts immediately after the canvas, before HUD, at z-index 0. This paints above the unpositioned canvas and below both later auto/zero HUD layers and positive layers. No native styles or elements are altered. Fixed coordinates, canvas bounds and pointer exclusion remain. Anchoring is checked before the unchanged-geometry early return, restoring the same SVG after canvas remount/reparent without repeated DOM writes. Missing, disconnected or uninsertable anchors hide the overlay. Persisted routes and drag previews share this layer.

## Verification limits

These are deterministic offline behavior tests, not pixel/browser validation. They establish a reproducible source defect but cannot establish that every flicker seen in the user's live session has the same cause. No real Brave/Violentmonkey/Drive session was accessed. No game orders, route data, permissions, network behavior or Drive code are changed. Independent review and frozen aggregate gate are required before publication; their final results accompany the release report.
