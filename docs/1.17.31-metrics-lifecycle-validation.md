# Vista de métricas al reanudar en1.17.31

## Reproducción y alcance

Base `d5fb89024266016145f1132177f1de1bbb4e985b`, árbol `9aff30fa923b1a46b7a2dedb6da5fab67c3eb37c`. Panel y adaptador productivos en VM con eventos, almacenamiento y reloj controlados. Se abre y selecciona un informe; se modela ausencia de ejecución del panel mientras otra pestaña cambia el consentimiento. La simulación entrega `pageshow` persistido antes de la notificación pendiente de almacenamiento. El checkbox y la copia anteriores siguen visibles en la base, aunque el núcleo ya respeta la revocación cuando se consulta. El fallo es de la vista, no una reactivación o escritura del núcleo.

El caso exacto `Restored metrics panels reconcile consent and selected copies before delayed storage notifications without writing` falla sobre las fuentes anteriores: checkbox observado `true`, esperado `false`. Se conserva el mismo test y dispatcher antes/después en copia aislada:

```bash
probe_dir=$(mktemp -d)
git archive d5fb89024266016145f1132177f1de1bbb4e985b | tar -x -C "$probe_dir"
cp tests/metrics-integration.test.cjs "$probe_dir/tests/metrics-integration.test.cjs"
(cd "$probe_dir" && node --test --test-name-pattern='Restored metrics panels reconcile consent' tests/metrics-integration.test.cjs)
```

[Chrome Page Lifecycle](https://developer.chrome.com/docs/web-platform/page-lifecycle-api) documenta tareas suspendidas al congelar páginas y los targets de `resume`/`visibilitychange` en `document` y `pageshow` en `window`. Eso sustenta modelar tareas diferidas; no establece un orden universal entre `storage` y `pageshow`. Aquí se prueba deliberadamente una frontera de orden, sin afirmar que haya ocurrido en la sesión del propietario o en BFCache real.

## Cambio y controles

La vista fuerza una lectura mediante `getReport()` al recibir `pageshow` persistido, `document.resume` o `visibilitychange` hacia visible. Una carga nueva ya hace su lectura inicial; ocultar la pestaña no provoca lecturas nuevas por visibilidad. No se llama a `record`, `setEnabled`, `startTiming` ni `finishTiming`. El refresco también invalida una copia seleccionada: una nueva generación puede estar habilitada cuando se procesa el evento, sin que eso permita conservar contadores revocados.

Las regresiones comprueban revocación con `storage` diferido; otra generación ya habilitada; eventos tardíos/duplicados sin escrituras; 31 días de reloj simulado y filtrado de retención; target incorrecto sin efecto; regreso visible con contadores actuales; y fallo de lectura que se muestra inmediatamente. Recuperar almacenamiento y reanudar repetidamente no elimina `forcedOff`: sigue haciendo falta activación explícita. No se restaura historial anterior.

El núcleo, el muestreo síncrono, sus relojes y el collector remoto no cambian. El token productivo de rendimiento se abre/cierra dentro de una ejecución síncrona de `step`, no entre tareas de navegación; no se inventa un token pendiente de BFCache para justificar esta corrección. Se mantienen todas las categorías, retención, permisos y elecciones guardadas. Los contadores siguen aislados por versión.

## Límites

Son simulaciones offline de eventos, reloj y concurrencia; no fuerzan suspensión del sistema operativo, descarte o BFCache real. Las pruebas reales de selección en Chromium de1.17.30 siguen en el gate, pero no se presentan como prueba de suspensión. No se modifica el juego, envían órdenes ni recogen datos personales. Una vista actual no equivale a bloqueo global entre pestañas. Los errores persistentes siguen requiriendo recuperación explícita y no se atribuye una causa de almacenamiento al propietario.
