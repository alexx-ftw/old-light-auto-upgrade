## Corrección y fronteras

Al volver el foco o estar visible, una pestaña sin sesión busca una autorización ya confirmada, válida, del mismo Client ID y con un ID distinto del último iniciado o retirado por esa pestaña. Reutiliza startLocalSession y verifica la cuenta mediante el runtime existente. No abre OAuth, no escribe ni extiende la autorización al restaurar y no añade un sondeo periódico. Eventos repetidos durante una sesión activa no reinician el runtime. Destruir elimina ambos listeners.

| Escenario | Resultado esperado y probado |
| --- | --- |
| A sin sesión; autorización explícita enB; volver aA | Recupera autorización compartida sin otra ventana/OAuth y conserva vencimiento absoluto. |
| Oculta y luego visible | No solicita mientras oculta; recupera al estar visible. |
| Otro Client ID o autorización caducada | No usa esa autorización ni inicia OAuth. |
| Desconectar; vista obsoleta del mismo ID; ID nuevo posterior | No revive el mismo ID; permite una nueva autorización confirmada. |
| Lectura de almacenamiento fallida o instancia destruida | Falla cerrada, sin solicitudes ni recuperación al foco. |
| Sesión activa, foco/visibilidad repetidos | No reinicia ni duplica solicitudes. |

## Caducidad del proveedor: parte detenida

[Google, Use the token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model#token_expiration), consultado durante esta revisión: un token de acceso tiene duración corta; al caducar hay que solicitar otro mediante requestAccessToken desde un evento del usuario. El código usa expires_in de Google menos30s prudentes (ejemplo ficticio3600s:59min30s). Recordar cuenta solo conserva el correo de selección; no genera refresh tokens ni permite acceso permanente. La prueba independiente conserva11recargas durante55min sin ventana/OAuth nuevo, sin prolongar vencimiento.

Por tanto, la renovación automática sin gesto queda detenida: con el modelo actual el usuario debe abrir Drive y pulsar Renovar conexión, completando la selección/autorización que Google solicite. No se cambia OAuth, scopes, permisos, credenciales ni configuración de seguridad para eludir este requisito.
