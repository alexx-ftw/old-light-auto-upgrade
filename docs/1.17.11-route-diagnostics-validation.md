# 1.17.11: explicar rutas activas con cola vacía

## Observación y alcance

Base publicada: `b83503cbf43e0e1b691646147a92a88e23c48924` (1.17.10). El propietario comunicó no haber observado ningún envío. La captura muestra la ruta propia Technocratic Imperium → Xethurn Throne 001 activa, reanudada, cada 15 minutos, con Probe/Marauder/Vanguard en excedente y reserva cero; cola 0 de 0. No contiene cantidades estacionadas, plazos guardados, antigüedad del censo, control de pestaña ni DOM. No demuestra que hayan transcurrido 15 minutos desde la reanudación ni un fallo de envío.

El panel omitía la condición efectiva de espera. Esta entrega corrige ese hueco comprobado, sin atribuir una causa definitiva a la partida. Las barreras de envío, propiedad/alianzas, reservas y requisitos de flota no se relajan. No se añaden accesos, credenciales, permisos ni eventos de telemetría.

## Reproducción antes/después

Se añadió sin modificar el harness existente `route card explains current wait and check time without replacing controls or issuing actions` en `tests/reinforcement-panel.test.cjs`. El mismo test con el panel de la base se ejecutó con:

```sh
env -u NODE_PATH node --test --test-name-pattern='route card explains current wait' tests/reinforcement-panel.test.cjs
```

Antes: AssertionError porque el texto de la tarjeta no contiene `Abre Structures o Shipyard` aunque se suministra ese diagnóstico. El panel anterior ignora el adaptador, muestra Activa/intervalo/composición y no explica la espera. No es reproducción causal de una avería del envío. Los nuevos tests de núcleo fallaban porque no existía la API de diagnóstico; se conservan como cobertura nueva, no como evidencia de la causa de la partida.

Después: la tarjeta muestra el motivo y la hora de comprobación local; cambiar la dependencia actualiza solo el texto y mantiene el mismo botón Editar. Consultar no crea, cancela ni reconcilia misiones, no navega ni persiste datos y no altera testigos de autorización. Las comprobaciones decisivas de flota/tránsito se explican mediante la misma función `plan` usada para preparar y revalidar la ruta. El adaptador de diagnóstico del contexto replica las barreras exteriores exclusivamente para presentación.

## Matriz offline

| Escenario | Resultado verificable |
| --- | --- |
| Controls nativos no visibles | Explica abrir Structures o Shipyard del origen; el panel Helper no los sustituye; recuperar HUD elimina ese motivo. |
| Helper pausado, pestaña oculta, importación/pedido en curso | Expone su impedimento; ningún efecto. |

| Recuperación de informes, selector/misión/reintento ocupado, diálogo o carga | Expone la condición exterior que impide preparar una nueva ruta. |
| Identidad/flota ilegibles, pausa imperial, edición de campo | Estado explícito; no modifica el contexto ni limpia la pausa. |
| Censo ausente, inválido o caducado | No anuncia ruta preparada; distingue la edad superior a dos minutos. |
| Origen o destino no presente como propio | Espera endpoints verificados; ninguna sustitución de identidad. |
| Excedente sin naves tras reserva | Explica cero cantidades; excedente no inicia producción. |
| Cantidad fija superior a flota disponible | Muestra tipo, disponible tras reserva y cantidad solicitada. |
| Intervalo futuro guardado | Muestra segundos restantes, sin deducir vencimiento del rótulo «cada 15 min». |
| Tránsito de esa ruta o hacia extremos con origen desconocido | Espera censo que demuestre asentamiento. |
| Otra ruta o misión del origen pendiente | Explica exclusión, conserva tickets/revisión. |
| Ticket recuperado en sending | No emite autorización; consultar no legitima la recuperación ni reconcilia. |
| Ruta válida sin bloqueante observado | Dice preparada para próxima comprobación, nunca enviada; siguen pendientes preflight nativo y protección. |
| Refresco repetido de tarjeta | Conserva identidad de controles y no ejecuta callbacks de edición/envío. |

Las pruebas generales existentes siguen verificando propietario, aliado protegido, tickets, flota/reserva, confirmación incierta, generación y coordinación. La puerta completa del commit final se conserva fuera del repositorio y debe aprobar todas las pruebas, sintaxis, builders e integridad. El informe independiente debe distinguir el hueco de visibilidad corregido de la causa todavía desconocida.

## Límites

La hora corresponde a una comprobación local de solo lectura; no representa un intento de envío. «Último envío confirmado» procede del registro local de la ruta y no enumera movimientos manuales o de otras instalaciones. No existe registro anterior de comprobaciones: se recalcula con los datos presentes, sin guardar historial. Un error de lectura muestra diagnóstico no disponible, nunca éxito. La prioridad del motivo explica la primera condición observada, no prueba que sea la única.

No se han usado Pepinillo, Brave/Violentmonkey real, Drive real, ni la partida. No se han enviado órdenes ni telemetría de diagnóstico. La captura es evidencia visual de esa interfaz en un instante; no verifica el estado actual. La experiencia renderizada y la causa exacta del no-envío comunicado permanecen pendientes. La siguiente observación de la nueva tarjeta permitirá pedir únicamente la evidencia que corresponda a su condición, sin modificar configuración o enviar naves por el usuario.
