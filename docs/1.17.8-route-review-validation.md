# Repeated route review: initial ownership census

## Evidence and reproduction

The reported screenshot shows a route with `La misión necesita revisión en la cola` and its linked mission with `Protección de aliados: falta propiedad reciente del juego. Envío pausado.` The native adapter previously returned `paused` for every initial ally-protection rejection. The route engine correctly treats a paused queue mission as requiring review, so an initially unavailable ownership census caused a review even though native preparation had never started. Repeating the route after acknowledgement could reproduce the same stop.

## Bounded correction

Only a route-owned mission (`route:` ID) rejected by the initial protection check with `ownership` or `unknown-owner` now returns `waiting`. It keeps its existing durable route and ticket, stays blocked from native preparation, and checks all guards again on a later ordinary queue pass. Queue retry backoff remains in force.

Protected targets, invalid scope, storage failures, unresolved aliases, unexpected exceptions and material route/action/fleet changes keep existing blocking behavior. Loss of protection evidence during native preparation still pauses for review. Confirmation uncertainty still requires review. The already-attempted claim check runs before the initial ownership check so missing data cannot downgrade a previously confirmed attempt from `uncertain` to retryable `waiting`.

Existing pending reviews are deliberately not cleared: their persisted records do not establish that a native send never occurred. Complete the existing review once, then resume the route when appropriate. This change prevents newly generated reviews for the proven initial-data case; it does not bypass human review of uncertain sends.

## Tests

`tests/ally-dispatch.test.cjs`: 33/33 pass on the candidate; 27 pass and 6 fail against unchanged baseline `a45e735` using the same regression suite. New coverage includes repeated missing/unknown/stale initial ownership, zero native preparation while blocked, same-claim recovery after fresh data, protected/in-flight failures remaining paused, confirmed-claim replay remaining uncertain, and the real route engine + queue + native adapter preserving its ticket through repeated waits before one confirmed send and cooldown.

The wider focused suite (`ally-*.test.cjs`, `reinforcement-*.test.cjs`, and `native-mission-custom.test.cjs`) passed 481/481 tests (including 23 independent-review regressions), with no failures or skips; userscript syntax also passed. Independent review and the final combined release gate are reported separately. Tests use deterministic DOM and storage doubles. No real game, Brave/Violentmonkey, Drive session, or user computer was accessed. The screenshot supports this concrete failure path; other genuine review causes remain possible.
