## Cambio acotado

- Cámara verificada sigue siendo primera opción. Un rechazo de hit-test con cámara disponible nunca usa fallback.
- Solo con cámara explícitamente indisponible: puntero trusted sin botones quieto durante al menos 300 ms, ficha visible de nombre propio único, posición a menos de 22 px y censo actual completo. Se lee la ficha actual, nunca anchors de flechas guardados. Navegación, pan, wheel, scope y pérdida de foco invalidan el punto previo.
- Destino propio distinto se verifica en la ficha nativa actual; si aún espera su demora nativa de 250 ms, se concede una ventana de 320 ms. El gesto solo abre un borrador para revisión.
- Captura pointerdown en window antes del listener nativo de document/canvas; pointer capture mantiene seguimiento, coordenadas fuera del canvas cancelan. La liberación implícita después de pointerup no se confunde con pérdida accidental de captura durante drag.
- Soltar Ctrl también cancela durante la espera del destino. Escape, blur, salida, pointercancel y pérdida accidental de captura cancelan. Sin origen verificado no se captura input ajeno.
- Las flechas requieren cámara; no se inventa transformación. El panel muestra motivo de cámara no disponible y los fallos de import/shape se propagan por el canal privado, sin datos de cuenta.

## Pruebas

Reproducción antes del cambio: misma suite extendida contra panel de HEAD, 75 tests, 64 aprobados y 11 fallidos. Incluye pan nativo activado por cámara indisponible y cancelaciones perdidas. Después del cambio: suite ampliada de panel y mapa, 103 tests aprobados. El harness propaga window → document → canvas y respeta stopImmediatePropagation; reproduce pointer/mouse, captura y liberación. Es una simulación causal, no una sesión de navegador.

Los builders, comprobaciones de sintaxis y suite completa se ejecutan sobre el candidato final con validate-release.cjs; el informe de publicación conserva el resultado exacto. No cambia lógica de envíos, requisitos de datos ni almacenamiento de rutas.
