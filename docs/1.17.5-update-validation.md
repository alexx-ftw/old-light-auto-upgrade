# 1.17.5: actualización al recargar

## Alcance

Base: candidata local 1.17.4, commit `36da5693dae0daefd20db8232211b0ef84d17001`. Se mantienen sus cambios de altura. La comprobación se inicia una vez al terminar el arranque local del helper, sin esperar a identidad del juego ni a Drive.

- Solicitud GM GET a una URL fija en raw.githubusercontent.com, `anonymous: true`, timeout GM de 8 segundos y watchdog local de 10 segundos. Solo HTTP 200 con URL final exacta, metadatos de hasta 16 KiB, nombre, namespace, updateURL y downloadURL esperados y versión numérica estricta de tres componentes. La respuesta nunca se evalúa ni se inyecta.
- Comparación numérica con la versión compilada en ejecución. Se rechazan versiones ambiguas, prereleases o componentes demasiado largos. Una cabecera remota inválida produce fallo cerrado.
- Web Locks serializa la consulta/marca/apertura entre pestañas del mismo origen. localStorage guarda una versión de forma síncrona antes de abrir la pestaña; la marca no entra en copias ni Drive. No se usa GM_getValue porque Violentmonkey puede mantener una caché distinta por pestaña. La página puede leer o alterar esta marca, pero no cambiar la URL fija del instalador. Un marcador malformado bloquea la apertura automática y deja disponible el intento manual. Borrar el almacenamiento del sitio restablece el historial de ofertas. Sin bloqueo o almacenamiento no hay apertura automática. No garantiza deduplicación entre perfiles/instalaciones distintas del gestor.
- La marca conserva la mayor versión ofrecida. Cancelar, cerrar el instalador o fallar su apertura no genera nuevas aperturas automáticas para esa versión. Esto prioriza evitar pestañas repetidas; el botón del pie permite un intento manual explícito.
- Solo GM_openInTab abre la URL fija de instalación. El usuario confirma en el gestor. No hay actualización silenciosa, clic automático en confirmaciones, protocolo privado del gestor ni ejecución de código remoto. La cabecera nunca cambia su versión mientras sigue ejecutándose el código anterior.
- Nuevos permisos: GM_openInTab y @connect raw.githubusercontent.com. Se conservan todos los permisos anteriores. El gestor puede pedir aceptación de los nuevos permisos.

## Comprobación automatizada

`node --test tests/helper-update-check.test.cjs` ejecuta la función productiva extraída del userscript, con dobles controlados de GM, red, timers y Web Locks. Cubre solicitud anónima y fija, versiones iguales/anteriores, comparación numérica, identidad/URL/duplicados/contenido no válidos, redirecciones, errores de red, watchdog y callback tardío, marcador entre recargas, 20 arranques concurrentes, almacenamiento fallido, apertura fallida y enlace manual.

Estas pruebas no demuestran comportamiento real del gestor, permisos o red: la ejecución en Brave/Violentmonkey sigue pendiente. La instalación confirmada por el usuario solo puede verificarse al ejecutar la nueva versión después de recargar. No se usa Chrome/Brave ni se envían órdenes al juego o consultas a Drive durante la validación.

## Referencias del gestor

- [GM_xmlhttpRequest](https://violentmonkey.github.io/api/gm/#gm_xmlhttprequest): petición privilegiada con modo anónimo, timeout y URL final.
- [GM_openInTab](https://violentmonkey.github.io/api/gm/#gm_openintab): apertura de pestaña del instalador; no equivale a instalar ni confirmar.
- La API pública no proporciona una actualización nativa silenciosa invocable por el userscript. Se mantiene la comprobación propia como aviso/apertura del instalador con confirmación del usuario.
