# 1.17.8: optional local performance samples

## Evidence and purpose

In the checked 1.17.7 tree `19c2655ed8c980639be40e3126185bc20137af26`, `createLocalMetrics.startTiming()` reads the performance clock only when the independent remote collector is enabled. Local-only users can inspect usage/error counters but have no step-duration information. This release adds that missing local diagnostic; it does not claim a newly discovered game regression or measure the user's actual session.

## Data and cost boundaries

- Local-only collection defaults on only when the browser-local consent key is absent, under the explicit owner request for telemetry defaults. Stored opt-outs, malformed/present-null records and storage failures are never overridden. No automatic enabled consent is written, avoiding startup versus opt-out races. No permission, service, remote destination, account linkage, or Drive field added.
- Five allowlisted counter names: `performance.step.lt4ms`, `lt16ms`, `lt50ms`, `lt200ms`, `gte200ms`. The existing UTC-day aggregate is retained; exact durations, sample times, URLs, identities, messages and game data are not stored.
- One eligible scheduled synchronous helper step per minute and tab. The gate avoids storage/performance-clock reads on intervening ticks. Sampling does not represent FPS, network latency, all steps or all long tasks.
- Pending samples are single-use and bound to the same consent generation through final recording. Revocation, deletion and re-enabling cannot resurrect a sample from earlier consent.
- The local bins bypass the forwarding wrapper and cannot enable or populate remote telemetry. Existing independently consented remote timing remains separate.
- Missing/throwing/nonfinite/negative performance clocks and elapsed durations over one minute are skipped. No timing failure is propagated into game work.
- Cross-tab activation can take up to the next one-minute probe during activity. Explicit activation in this tab resets the probe. Existing retention and per-version reset semantics remain unchanged.

## Automated verification

`tests/metrics-timing.test.cjs` covers bucket boundaries, disabled sampling, 10,000 repeat ticks without further storage/clock accesses, the minute boundary, revocation/re-enabling, invalid clocks and stale/single-use tokens. `tests/telemetry-integration.test.cjs` checks local-only operation, independent remote consent and no remote forwarding of local bins. The independent review records additional adversarial tests and findings in `1.17.8-timing-review.md`.

The release requires the complete clean-tree `node validate-release.cjs` gate, including every test, syntax checks, version agreement, reproducible builders, feedback regressions and final integrity. Final result and exact checked tree are recorded with the publication checkpoint. Focused test passes alone do not authorize publication.

## Limits

All validation here is offline. No live Brave/Violentmonkey, browser FPS, Drive authorization or actual game-session behavior was tested. Existing 1.17.7 arrow behavior remains unverified in the user's live session. No game action was performed. These samples help diagnose future reports when local metrics are enabled and the user later shares the report. Default-on local collection is not remote transmission.
